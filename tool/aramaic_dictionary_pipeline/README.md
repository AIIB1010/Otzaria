# צינור הרחבת המילון הארמי-עברי

כלי הכנת נתונים (Python, לא חלק מהאפליקציה) שמרחיב את `assets/dictionary.json` ("מילון פשיטא") ממקורות נוספים,
עם דגש על דיוק: הבחנה בין כפילות, ניסוח שקול, משמעות שונה וצורה דקדוקית, תיעוד מלא של כל החלטה,
ואישור אנושי לכל מה שאינו ודאי טכנית. האפליקציה אינה מריצה אף אחד מהשלבים האלה.

## מקורות

| מקור | קלט | הערות |
|---|---|---|
| שפתי גיטין, שפתי ברכות (הרב י. אביקסיס) | PDF עם שכבת טקסט | נתיבים ב-`config.local.json` (ראו "הרצה") |
| ויקימילון העברי | MediaWiki API, קטגוריה "ערכים בשפה הארמית" | CC BY-SA 4.0 — ראו "זכויות" |
| המילון הקיים | `assets/dictionary.json` (גיבוי מ-git blob) | "פשיטא" הוא יעד המיזוג; שיח ישראל / אונקלוס משמשים להצלבה בלבד ואינם משתנים |

## מה האפליקציה עושה עם הקובץ (סקר קוד)

* תצוגה, תפריט הקשר ו-API לתוספים (`DictionaryLookupRepository`) טוענים **רק** `"מילון פשיטא"`.
* מנוע החיפוש (Rust, חבילת `otzaria_search_engine`, `lexicons.rs`) ממזג **את כל** המילונים שבקובץ להרחבת "תרגום ארמי"
  (מילה בודדת בלבד; עד 16 הרחבות לכל מילה; ראשונים מנצחים). לכן ערך שגוי בכל אחד מהמילונים משפיע על החיפוש.
  `search_expansion_impact.py` מדמה את זה ומדווח אילו הרחבות קיימות אבדו ולמה (תקרה, או שינוי מאושר של פירוש למילה אחת לצירוף).
* `findAramaicMatches` מחזיר כל ערך שמכיל את המילה כמילה שלמה, וללא תקרה: אחרי הוספת אלפי ביטויים, "ליה" מניבה עשרות
  שורות בתפריט ההקשר. נוספה תקרה אופציונלית `maxContainingMatches` (ברירת מחדל: ללא תקרה; בתפריט ההקשר: 8).

## הרצה

```
py -m pip install pymupdf openpyxl
copy config.json config.local.json    # וערוך: work_dir, sources.siftey_*.pdf  (הקובץ אינו נכנס ל-git)
py run_all.py                         # הכול: baseline → חילוץ → נרמול → סיווג → מיזוג → ייצוא → בקרה
py run_all.py --skip-extract          # מהנרמול והלאה
py reports.py                         # 13 דו"חות CSV + all_reports.xlsx
py review/server.py                   # כלי בקרה ידנית: http://127.0.0.1:8765
py export.py --write-asset            # כתיבה ל-assets/dictionary.json (אחרי validate.py)
py -m unittest discover -s tests      # בדיקות הצינור
```

הרצה חוזרת על אותם קלטים ואותן החלטות נותנת אותו פלט (מזהים יציבים, מפתחות ממוינים, אין תלות בזמן/אקראיות).
קבצי ה-PDF והנתונים הגדולים נשארים ב-`work_dir` מחוץ ל-git.

### חילוץ ה-PDF — עיקרי הממצאים

* שכבת הטקסט תקינה; OCR לא הופעל (דף 3 בגיטין הוא מכתב הסכמה כתמונה, דפים 4 ו-8 ריקים).
* הסדר הלוגי של ה-PDF אמין, אך סוגריים מגיעים הפוכים וסדר התווים בתוך span אינו אמין ליד סוגריים/מקפים — לכן הסידור נעשה
  ברמת התו לפי מיקום (ימין→שמאל).
* גופן PFT_Vilna = המילה הארמית, FrankRuehl-XP = התרגום; כותרות דף ב-EFT_Tefilot. כל span מסווג, ולכל עמוד נספרות האותיות
  העבריות שחולצו מול `get_text()` של העמוד (בקרת שלמות עצמאית; **אפס אותיות חסרות** בשני הספרים).
* `U+E802` / `U+E803` בגופן העברי הם גליפים מורכבים של ך סופית עם ניקוד (ךְ / ךָ) ולא קישוט: מוחזרים כ-"ך".
* ניקוד בתרגום נשמר ב-PDF כתווים ברוחב אפס שאי אפשר למקם; לכן בערכים שאבד בהם ניקוד התרגום מוצג ללא ניקוד (`niqqud_lost`).
* פסקאות הסבר למילים עבריות שבתחילת דפים (גיטין) מסומנות `region: hebrew_notes` ומחוץ למילון.
* כל רשומה כוללת עמוד PDF, דף ועמוד בש"ס, טור/שורה, תיבת גבולות (`bbox`), קטע מקור וציון ביטחון.
  כלי הבקרה מציג את אזור העמוד המקורי עם הדגשה.

## מדיניות ההכרעה

1. **אוטומטי רק כשהוא ודאי טכנית** (`classify_senses.py`): זהות טקסטואלית אחרי נרמול בטוח; אותה קבוצת מילים נרדפות בסדר/פיסוק
   שונה; הכלה מלאה בפירוש קיים בלי הערת-הקשר נוספת; מפתח חדש לגמרי עם פירוש יחיד, נקי, בביטחון חילוץ ≥ 0.9 וממקור מותר.
2. **כל השאר לתור בקרה** עם *הצעה*: משמעות שונה (`distinct_sense`), חפיפה חלקית, הבדל דקדוקי (`grammatical_variant` — רמז בלבד),
   הערת-הקשר שתאבד, סתירה, חילוץ חשוד, מפתח של 4 מילים ומעלה (קטע משפט), וכל ערך שמקורו בוויקימילון.
3. אין מיזוג טרנזיטיבי (א~ב, ב~ג ⇏ א~ג); אין איחוד אותיות (ה/א, ם/ן); אין stemming במיזוג; אין תיקון כתיב אוטומטי.
4. אף פירוש קיים אינו נמחק או נדרס. הצעה לשינוי פירוש קיים מסומנת במפורש ותמיד דורשת אישור **ייעודי**: `merge.py` מחיל שינוי רק
   כשבהחלטה יש `confirm_modify_existing: true` (עמוד `/mods` בכלי הבקרה); אישור רגיל של פריט אינו מספיק, והשינוי הלא-מאושר נרשם
   ביומן כ-`modification_not_confirmed`.
   * `manual_key_corrections.json`: תיקוני מפתח ידניים מתועדים (מפתח מרובה צורות, אות אופציונלית, הערת גרסה) ותיקון טקסט בודד;
     כל תיקון נבדק מול העמוד המקורי ורשום ביומן כ-`manual_key_correction`.
   * `normalize.py` מסיר הערת גרסה "[הג' הב"ח …]" מראש מפתח (נשאר רק מה שבתוכה) ומסמן `variant_reading_prefix_stripped`.
   * מפריד "\" שהספר מדפיס בפירושים מומר ל-"/" בעת הוספת משמעות חדשה (הטקסט המקורי נשמר ביומן ב-`source_text`).
5. סיווגים: `exact_duplicate`, `semantic_duplicate`, `distinct_sense`, `grammatical_variant`, `orthographic_variant`,
   `conflicting_sources`, `uncertain`, `rejected`.
6. **ויקימילון — כל ערך מחייב אישור אנושי מפורש**, גם כשהוא כפילות. הסוכן סוקר אותו פריט-פריט
   (`review/wikt_suggestions.py`) אך זו הצעה בלבד.
7. **סוכני AI מסייעים** (`review/AGENT_BRIEF.md`, `review/agent_validate.py`): מציעים החלטה לכל פריט בתור, ללא סמכות.
   המאמת אוכף שלא הומצאו מילים שאינן בטענות הפריט. הצעות נשמרות בנפרד ואינן נכנסות לייצוא בלי `--include-agent-suggestions`
   (תצוגה מקדימה/בדיקות בלבד) או אישור אנושי.

### מה כבר ידוע שדורש תשומת לב

* **הומוגרפים של מילים שכיחות** (למשל "אמר"=טלה, "טעם", "מן", "סימן", "רומא", "פטיש") נפסלו בהצעות ויקימילון כי הם יציפו את תפריט
  ההקשר בערך מטעה.
* שגיאות דפוס בספרים עצמם (למשל "ינשם", סוגר לא מאוזן) — מועברות לבדיקה ואינן מתוקנות אוטומטית.

## כלי הבקרה

`py review/server.py` — רשימת פריטים עם מסננים, פירושים קיימים, טענות עם קישור לעמוד המקורי, הצעת מערכת והצעת סוכן, עריכת ניסוח,
אישור/פסילה/"דורש בדיקה"/חזרה להחלטה קודמת. החלטות נשמרות ב-`review/decisions.jsonl` (הוספה בלבד, `fsync`); אפשר להפסיק ולחדש.
אחרי הבקרה: `py merge.py && py export.py && py validate.py && py reports.py`.

## בדיקות

* `validate.py` (קוד יציאה ≠ 0 בכשל): JSON/UTF-8/LF ופורמט זהה ל-`json.dumps(indent=2)`; מבנה; מפתחות/פירושים ריקים; הפרדת `***`;
  מילונים אחרים זהים לגיבוי; **כל פירוש קיים נשמר** (או שינוי מתועד); רגרסיה ל-אברא/אהני/אגמרך/איבעי; אין כפילות פירוש חדשה בערך;
  מיון; תחביר אוצריא ותווים חשודים בפירושים חדשים.
* `tests/` — בדיקות יחידה לנרמול, סיווג, מיזוג, ייצוא, חילוץ וויקימילון.
* Dart: `test/tools/dictionary/aramaic_dictionary_asset_test.dart` (מבנה, פענוח `AramaicDictionaryEntryPresentation.parse` לכל ערך, מיון,
  רגרסיה, חיפוש ארמית↔עברית וללא ניקוד, זמן טעינה, תקרת תפריט ההקשר) ו-`dictionary_lookup_repository_test.dart`.

## מגבלות

* סוכן ה-AI אינו אומת מול מילונים חיצוניים (יסטרו, סוקולוף); ההצעות נשענות על הטקסט שבפריט ועל ידע לשוני.
* סימולציית ההרחבה בחיפוש היא העתק לוגיקה בפייתון, לא הרצת המנוע עצמו.
* הניקוד בתרגום אבד (ראו לעיל) — התרגומים החדשים מוצגים בדרך כלל ללא ניקוד.
